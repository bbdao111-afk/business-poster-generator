# 零指向脱敏规范（对外发布强制门禁）

**触发条件**：把本 Skill、示例 brief、模板、截图、字体包或任何衍生物**发布到公开仓库、交付第三方、发到社群或写进博客**之前。

## 0. 先分清两种产物（搞混会出严重错误）

| 产物 | 是否脱敏 | 原因 |
|---|---|---|
| **真实交付海报**（给客户/渠道/印刷） | ❌ **绝不脱敏** | 产品名、客户名、品牌口径是事实本身；替换等于造假，违反「文案口径与原始材料逐字一致」 |
| **对外公开的 Skill / 示例 / 截图 / 模板** | ✅ **必须零指向** | 示例只用于说明机制，携带真实公司、产品、客户、内部流程即构成信息泄露 |

一句话：**真实海报保真，公开示例脱敏。** 不得把脱敏规则套到交付物上，也不得把交付物直接当示例上传。

## 1. 四类禁止出现的指向信息

| 类别 | 具体项 | 占位写法 |
|---|---|---|
| **厂商指向** | 公司全称/简称/商标/英文名、品牌色命名（如"××蓝"）、官网域名、注册商标符号组合 | `示例科技 DEMOTECH` |
| **产品指向** | 真实产品名、物料名、内部代号、版本号与套餐名绑定关系 | `AI 助手` / `示例平台` / `V1.0` |
| **客户指向** | 客户名称、行业+规模+场景可反推的组合、厂区/机房实景照、客户 Logo、访谈原话 | `示例制造`（科技制造领域成长型企业） |
| **内部指向** | 接口人姓名与联系方式、内部系统名与路径、发文/工单编号、报价审批口径、"仅限内部公开"标记、内网域名 | `内部报价系统` / `内部系统路径`，编号与人名直接删除 |

字体、配色、版式本身可以保留（不构成指向）；但**图片要重做**：截图里的标题栏、菜单名、Logo、水印、URL 都是指向信息，裁掉一角没用，必须整张替换。

## 2. 强制流程（三步，缺一不可）

```bash
# ① 建你自己的禁词表（机器无法自动识别你公司的真实名称，必须由你提供）
cp assets/pointing-terms.example.txt ./my-terms.txt   # 逐行填入公司名/英文名/产品名/客户名/内部系统名

# ② 扫描待发布内容
python3 scripts/check_pointing_info.py --terms ./my-terms.txt <要发布的目录或文件>

# ③ error 清零才允许发布；只改仓库副本，不动原始素材
python3 scripts/check_pointing_info.py --terms ./my-terms.txt --format github   # CI 用这个
```

判定级别：

- **error**（阻断）：邮箱、手机号、座机、内网域名、真实编号值、密钥令牌、IM 账号，以及**自定义禁词命中**。
- **warn**（默认不阻断）：`接口人`、`发文编号`、`仅限内部公开` 这类词——规范正文本身要描述规则，无法回避。若某行确属规则说明，在行尾加 `pointing:allow` 豁免。

## 3. 图片与二进制素材

脚本只扫文本。以下必须人工过一遍：

- [ ] 截图：换成合成图（可用 `assets/demo/` 的做法：中性窗口 + "示例界面 · 非真实产品" 角标）
- [ ] Logo：换成中性标识，图形不得与真实厂商标识近似
- [ ] 实景照片（厂区/机房/园区）：整张移除或换为无文字抽象背景
- [ ] 文件名与目录名：`assets/<真实项目名>/` 本身就是指向信息，一并改名
- [ ] PDF/Office 原件：**永不进公开仓库**，只保留从中提炼后的中性文本
- [ ] Git 历史：脱敏前的提交仍在历史里可翻出来。首次公开前用全新历史单条提交（`rm -rf .git && git init`），已公开过则需重写历史或删库重建

## 4. 脱敏时的保真约束

- 只替换**指称**，不替换**数据**：`"value": "1000点"` 这类口径、单位、比较基准原样保留。
- 若真实名称与数据强绑定（如"每 1000 点一套"属于某具体套餐），把整条示例改为中性自造数据，而不是只改名字留下数据——否则会拼出真实商务条款。
- 示例文件必须显式标注：`"source_note": "示例内容，仅用于模板验证；实际数据以用户提供材料为准。"`

## 5. 交付/发布前最后一句

> 公开仓库里的东西**删不干净**：fork、缓存、爬虫、镜像都会留下副本。上传前问一句"这条信息泄露了，我能不能承担"，不能就不传。
