# 海报生成流程（三步门禁）

本 Skill 按**一问一答、逐步推进**的方式工作。每个阶段结束都必须停下来等用户确认，
**未拿到确认不允许进入下一阶段**，也不允许"边做边补"直接把成品做出来。

三个阶段：`① 素材收集与核验 → ② 方案选版（强制等待选择）→ ③ 成品输出`。

---

## 第一步：素材收集与核验

### 1.1 先给清单，不要先动手

收到需求后，**第一件事是输出素材清单**，而不是开始做海报。按类型选一张表给用户：

**客户案例海报**

| 必选 | 字段 | 要求 | 状态 |
|---|---|---|---|
| ✅ | 客户名称 | 正式简称 | ☐ |
| ✅ | 客户 Logo | 透明底 PNG，清晰原图 | ☐ |
| ✅ | 公司 Logo | 示例科技公司 Logo，透明底优先 | ☐ |
| ✅ | 案例介绍 | Word/PDF/文字，含场景、问题、方案、变化 | ☐ |
| ✅ | 背景图片 | 客户实景或行业场景图 | ☐ |
| 可选 | 海报大标题 | 不提供则自动提炼 | ☐ |
| 可选 | 二维码 | 不提供则留占位，不造假码 | ☐ |

**产品宣传海报**

| 必选 | 字段 | 要求 | 状态 |
|---|---|---|---|
| ✅ | 公司 Logo | 左上角固定位 | ☐ |
| ✅ | 产品名称与一句话卖点 | 副标题支持 `{关键词}` 高亮 | ☐ |
| ✅ | 指标数据 | 2–4 个，每个给「值 + 标签 + 口径」三行 | ☐ |
| ✅ | 界面截图 | 2–4 张；**缺截图海报会明显发空** | ☐ |
| ✅ | 素材原文 | 彩页/上市通知/方案 PDF | ☐ |
| 可选 | 套餐内容表 | 一个套餐含多款物料时必给，否则讲不清组成 | ☐ |
| 可选 | 价格声明 | 如「最终报价以 内部报价系统为准」 | ☐ |

### 1.2 逐项核验

收到素材后逐项检查并**把结果写在回复里**：

- Logo 是否清晰、是否需要裁掉透明留白（带大留白的图缩小后会显得极小）
- 图片尺寸是否够、竖版裁切是否合适
- 数据是否有口径和比较基准
- 哪些是原文事实、哪些是营销表达、哪些缺失
- 内部材料里的接口人、内部系统路径、发文编号、**"仅限内部公开"标记一律不进海报**

### 1.3 内容提炼

把材料拆成「项目背景 / 挑战痛点 / 解决方案 / 案例价值」或「产品概述 / 关键指标 / 套餐组成 / 核心能力」，
没有原文依据的内容明确标注为**营销改写**，不补造客户名称、百分比、排名、型号。

### 1.4 🚦 门禁一（GATE 1）

打印下面这段再停下：

```text
【第一步完成】素材核验结果
✅ 已收到：……
⚠️ 缺失（需补充）：……
📌 标注为营销改写的内容：……

请补齐缺失项，或回复"按现有素材继续"确认进入第二步。
```

**必选项有缺且用户未明确放行 → 停在这里，不进第二步。**

---

## 第二步：方案选版（强制等待用户选择）

### 2.1 必须同时给出三类选项

不能只给一种方案让用户"看着办"，必须给出**可编号选择**的候选：

**A. 大标题文案候选（3–5 条）**

- 一张海报只表达一个主结论；两行以内；8–16 个汉字
- 避免没有原文依据的"领先、第一、行业标杆"
- 用 `{}` 标记要分色的关键词

**B. 字体 × 效果 × 配色**

用选版页和方案册呈现（不是嘴上描述）：

```bash
# 9 字体 × 11 效果可交互选版
python3 art-type/scripts/make_select_page.py "标题{关键词}" --output <目录> --default-fx block-tech

# 多条标题候选 × 指定主题的方案册
python3 scripts/make_options.py --output <目录> --theme light \
  --option "AI 助手-{Q4冲刺套餐}|sans|block-tech" \
  --option "{AI 助手}-Q4冲刺套餐|pangmen|dual-tone"
```

**C. 版式与背景方向**

- 产品版（浅底 794×1123）还是案例版（深底 1080×1440）
- 指标区：4 张单卡 还是 2 张品牌色渐变大卡
- 是否放套餐内容表、是否放界面实拍

### 2.2 输出选项卡片

每一项都要**编号 + 渲染预览 + 一句话说明 + 复制可用的字段**，例如：

```text
① 标题：AI 助手-{Q4冲刺套餐}
   字体：思源黑体 Heavy（sans）  效果：斜切渐变块反白（block-tech）
   观感：标题是整张海报唯一的深蓝色块，白字反白，清晰度最高
   brief 字段：title_font="sans", title_effect="block-tech"
```

### 2.3 🚦 门禁二（GATE 2）

```text
【第二步完成】共 N 个方案
① …… ② …… ③ ……
请回复编号（如"选 ②"，或"标题用 ①、字体换 04"）确认后，我再出成品海报。
未确认前我不会渲染成品。
```

**未收到明确选择 → 只重出选项，绝不生成成品海报。**

### 2.4 接受的选择回复形式

- 「选 2」「选 D」——整组采纳
- 「标题用 1，字体用 04」——跨维度组合
- 「② 但标题改成 ……」——采纳 + 局部修改
- 「除了 ③ 都行，你定」——用户授权后自行选定并说明

收到修改意见后，**回到第二步重出选项并重新等确认**，不要直接改成成品。

## 第三步：成品输出

仅在通过门禁二之后执行。

### 3.1 渲染

```bash
python3 scripts/render_poster.py <brief.json> --output <poster.html>
```

### 3.2 导出

```bash
python3 scripts/export_png.py <poster.html> --output <poster@300.png> --dpi 300
```

- 产品版 300 DPI = 2481×3509px；案例版 = 3375×4500px
- `--dpi 96` 仅作快速预览，**不要用系统截屏当交付图**

### 3.3 出图后质检（逐条核对）

- [ ] 文案口径与原始材料逐字一致（如"AI 助手授权"不是"AI 桌面云授权"）
- [ ] 多笔画标题字（服、刺、套、基、座）一眼可辨，无糊字无重影
- [ ] 4 张界面截图比例一致、绿标签齐平
- [ ] 表格/卡片未溢出、底部 CTA 条完整（取底部像素确认不是白边）
- [ ] Logo 未被裁切、未变形
- [ ] 数字、单位、上市/退市时间、免责声明齐全
- [ ] 无内部信息（接口人、内部系统路径、发文编号、内部公开标记）<!-- pointing:allow -->

### 3.4 交付

同时给出 `brief.json`（可复现）、`poster.html`（可编辑）、`poster@300.png`（可印刷），
并列出所有未被原文直接支持的营销改写。

### 3.5 修改轮次

- 改文案 / 换截图 → 局部改完直接重出，不必重走选版
- 改字体 / 改效果 / 改版式 → **回到第二步**，重出选项再等确认
- 改主题 / 换客户 / 换素材 → 回到第一步

### 3.6 对外发布（可选，但一旦触发就是硬门禁）

交付物自用/给客户 → 不脱敏，保持真实名称与口径。
把 Skill、示例、截图、模板上传公开仓库或发给第三方 → **必须零指向**：

```bash
cp assets/pointing-terms.example.txt ./my-terms.txt   # 填入你的公司名/产品名/客户名/内部系统名
python3 scripts/check_pointing_info.py --terms ./my-terms.txt <要发布的路径>
```

error 未清零不得 `git push` / 不得发包。图片、Logo、目录名、Git 历史要一起处理，完整清单见 [零指向脱敏规范](desensitize.md)。

## 门禁的固定写法（必须照做）

每个阶段结束都必须：① 给出本阶段结果；② 明确写出"请确认/请选择"；③ 说明未确认前不会继续。
**不要用"我先按这个做了，你看行不行"这类话术绕过门禁。**
